8-Way Block-Set-Associative Cache:
LRU vs MRU replacement

A simulator for Machine 9. It models an 8-way set-associative cache in front of a 1024-block main memory, runs the three required access patterns, and reports hit/miss statistics, average memory access time, and a full trace log. Every run also shows the same sequence under both LRU and MRU so the two policies can be compared directly.

Open the simulator

How to use it

1Set the parameters

Pick a block size (words, power of 2, min 2) and the number of cache blocks (power of 2, min 8 - an 8-way cache needs at least one full set). Sets are computed as blocks ÷ 8, and a memory block maps to set = block mod sets.

2Pick the policies

Choose the replacement policy: LRU, MRU, or Both, which runs the two caches on the same sequence and animates them side by side so every step can be compared directly. Also pick the read policy (non-load-through or load-through), which changes the miss penalty.

3Choose a test case

Test a is the sequential pattern, b is the mid-repeat pattern, and c is 64 random accesses in the range 0-1023. The random case takes a seed so a run can be reproduced exactly.

4Run and inspect

Press Run simulation. Use the view toggle for either a step-by-step animation (play, step, scrub) or the final snapshot only. The trace log is always generated and can be downloaded as a text file.

What the display means

Each row is one cache set with its 8 ways. A cell shows the memory block currently stored in that way. The thin blue bar at the bottom of a cell is its recency inside the set: a full bar is the most recently used block, a short bar is the least recently used. The MRU/LRU badges mark the two candidates that matter for replacement. During the animation, a green flash is a hit, a red flash is a miss (block placed), and an amber border means a block was evicted on that step.
